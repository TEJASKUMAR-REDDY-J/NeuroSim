# AI Mode · Neural Surrogate Laboratory

AI Mode turns the NeuroSim window into a workspace for one question:

> Can this neural model reproduce or accelerate this physics simulation, and under what conditions does it fail?

It is not a chat assistant. It is an experiment bench that uses the existing solver, run history, analytics
and renderer. Click **AI Mode** in the top bar (or **Use as ground truth · AI experiment** in the Runs panel);
**← Simulation Mode** goes back. A simulation running in Simulation Mode keeps running.

## Workflow

```
Physics (a NeuroSim case or run)
  -> Dataset      solver runs with a field-export schedule, one per condition value
  -> Model        FNO, CNN, persistence baseline, or your TorchScript / ONNX / Python model
  -> Training     autoregressive unrolling over each sequence (built-in models, PyTorch on the CPU)
  -> Evaluation   rollouts from the first state of every simulation, compared with the solver
  -> Generalization  training conditions vs unseen test conditions
  -> Results      summary, benchmarks, analytics
```

The pipeline strip at the top of AI Mode shows the state of each stage; click a stage to jump to it.

## Ground truth

**New AI Experiment** takes the current setup or any run from the history. Geometry, grid, flow, boundaries,
physics extensions and solver settings carry over unchanged (`case.json` of the experiment). Only FluidX3D is
integrated; OpenFOAM and SU2 are listed as not integrated.

Datasets are generated by the normal solver: each condition value becomes a run in the history
(`AI data …`) with `export_every` set, so the solver writes `rho`, `u`, `flags` (and `T`) at fixed steps,
including the initial state. NeuroSim converts them to the selected fields:

| Field | Channels | Definition |
|---|---|---|
| velocity | ux, uy (2D) / ux, uy, uz | lattice units |
| pressure | p | (rho − 1) / 3, lattice units |
| density | rho | |
| temperature | T | heat-transfer cases only |
| vorticity | wz (2D) / wx, wy, wz | curl of u, cell units |

Spatial downsampling is a fluid-weighted block average; a dataset cell is solid when most of its block is.
The Datasets page estimates simulations, sequences, dataset size, temporary export size and solver time
(from the Hardware benchmark) before anything runs.

## Conditions and stress tests

What the surrogate sees in training versus what it must handle in testing:

| Condition | Changed in the case |
|---|---|
| Reynolds number | `flow.re` (viscosity follows) |
| Inflow velocity | `flow.u` at fixed viscosity, so Re follows the velocity |
| Geometry | first object: primitive shape or library model, same size and position |
| Resolution | grid, object sizes and time sampling scaled together (same physical times); the dataset grid scales too |
| Temporal horizon | recorded steps multiplied for test runs |
| Lateral boundaries | faces normal to the flow (not 2D z faces) |
| None | one simulation split in time (train / validation / test fractions) |

One-click presets: Interpolation, Extrapolation, Unseen geometry, Resolution shift, Long rollout, Boundary
shift, Distribution shift (test values drawn log-uniformly, seeded), Custom. Values: comma separated, or
`a:b:n` for n evenly spaced numbers.

## Models

Built-in (PyTorch, trained on the CPU):

- **FNO**: lifting, Fourier layers (low modes per axis, padded for the non-periodic domain), projection.
- **CNN**: residual 3×3 convolutions with replicate padding.
- **Persistence baseline**: next state = current state. Every useful model must beat it.

All built-in models predict the change of the normalized state; the last layer starts at zero, so an untrained
model is the persistence baseline. Inputs: state channels, solid mask and, for Reynolds-number or velocity
conditions, the normalized condition value. The loss is measured in units of the typical one-step change over
fluid cells; before training, the same loss of the persistence baseline is measured on the validation sequences
and drawn as the reference line of the loss chart. GNN and NCA appear as plugin slots and are not part of this build.

External models (Models → Load…):

| Kind | Contract |
|---|---|
| TorchScript `.pt` | `model(x) -> y` |
| ONNX `.onnx` | first input `x`, first output `y` (ONNX Runtime, CPU) |
| Python adapter `.py` | class `Surrogate(manifest)` with `predict(x)` and optional `fit(train)` |

`x` is float32 `[1, C + 1 + K, *S]`: the state channels in physical (lattice) units in the order of
`manifest.json` `channels`, the solid mask, and K condition values (K = 1 for Reynolds-number or velocity
conditions, otherwise 0). `y` is the next state `[1, C, *S]`. `*S` is `(Y, X)` for 2D datasets and `(Z, Y, X)`
for 3D ones. NeuroSim resets solid cells after each step. See `examples/surrogate_adapter.py`.

## Evaluation

Each model rolls out autoregressively from the first state of every simulation (training and test conditions)
for the whole recorded horizon. Metrics are over fluid cells of the dataset grid, per step, then averaged:

- relative L1 and L2 of velocity, maximum error relative to the peak speed, MSE and MAE (lattice units)
- relative L2 per field (scalar fields relative to their fluctuation about the mean)
- mass error |Σρ − Σρ_true| / Σρ_true (from density or pressure), momentum and kinetic-energy errors
- stable rollout: steps until the velocity relative L2 exceeds 50 % or the state stops being finite
- solver time = measured kernel time per step at the solver grid × steps covered; surrogate time = measured
  rollout wall time (one untimed warm-up step); speedup = their ratio
- memory: solver device memory vs model parameters plus input and output state

Drag and lift errors are not reported: surrogates predict flow fields, and forces need the solver's boundary
populations. The comparison view shows ground truth, surrogate and difference with a shared timestep, as slices
or in 3D. The 3D view runs three render-only solver processes (the same renderer as Simulation Mode, `load`
command of the worker) with synchronized cameras.

## Files

An experiment is a directory in `workspace/runs/` next to simulation runs:

```
run.json          kind "ai_experiment", status, provenance, ground-truth parameters
case.json         ground-truth case
experiment.json   condition, dataset settings, models
dataset/          manifest.json, sim_K.npy [T, C, Z, Y, X], mask_K.npy
models/<id>/      weights.pt, train.jsonl (per epoch), model.json
eval/<id>.json    per-step and per-simulation metrics; eval/<id>_sK_<split>.npy predicted rollouts
summary.json      surrogate experiment summary
viewers/          render-only processes of the 3D comparison
```

`neurosim/analytics.py` reads simulations and experiments into one table (Analytics page).
